# Практическая работа №6. REST API с базой данных SQLite

## 1. Команды установки и запуска
Для запуска проекта откройте терминал (CMD) в папке `internet-technologies/06` и выполните:
1. Установите зависимости: `npm install`
2. Запустите сервер: `npm start`

После запуска сервер будет доступен по адресу `http://localhost:3000`. При первом запуске автоматически создастся файл базы данных `data.db`, а также таблица `books` с начальными данными (4 книги).

## 2. Схема таблицы
Таблица `books` создается в базе данных автоматически при первом старте приложения.
- `id` (INTEGER PRIMARY KEY AUTOINCREMENT) — уникальный идентификатор, генерируется автоматически.
- `title` (TEXT NOT NULL) — название книги.
- `author` (TEXT NOT NULL) — автор книги.
- `year` (INTEGER) — год издания.
- `available` (INTEGER NOT NULL DEFAULT 1) — доступность (1 — доступна, 0 — недоступна).

## 3. Список маршрутов
В API реализован полный CRUD.

| Метод | URL | SQL-запрос | Успешный код | Ошибки |
| :--- | :--- | :--- | :--- | :--- |
| GET | `/api/books` | `SELECT` с фильтрацией | 200 | — |
| GET | `/api/books/:id` | `SELECT WHERE id = ?` | 200 | 404 |
| POST | `/api/books` | `INSERT INTO` | 201 | 400 |
| PATCH | `/api/books/:id` | `UPDATE WHERE id = ?` | 200 | 400, 404 |
| DELETE | `/api/books/:id` | `DELETE WHERE id = ?` | 204 | 404 |

## 4. Примеры POST и PATCH

**Пример POST (создание книги):**
Отправьте JSON через Postman, curl или консоль браузера:
`POST /api/books`
Тело запроса:
`{"title": "Гарри Поттер", "author": "Роулинг", "year": 1997, "available": true}`
Успешный ответ: **201 Created** и созданный объект с новым `id`.

**Пример PATCH (частичное изменение):**
`PATCH /api/books/1`
Тело запроса (меняем только доступность):
`{"available": false}`
Успешный ответ: **200 OK** и обновленный объект (остальные поля сохранят старые значения).

## 5. Query-параметры (фильтрация в SQL)
Сервер выполняет фильтрацию на уровне базы данных с помощью `WHERE`. Все входящие значения передаются через параметры `?` (защита от SQL-инъекций).
- `GET /api/books?available=true` — вернет книги, у которых поле `available` равно 1.
- `GET /api/books?author=Булгаков` — вернет книги автора (частичное совпадение через `LIKE`).
- `GET /api/books?q=война` — поиск по названию через `LIKE`.

## 6. Правила валидации
- **Обязательные поля:** при `POST` и `PATCH` поля `title` и `author` обязательны. Если они пустые или отсутствуют, сервер вернет код **400 Bad Request** с JSON-ошибкой.
- **Несуществующий ID:** при запросах `GET`, `PATCH` или `DELETE` к несуществующему `id` сервер вернет код **404 Not Found**.
- **Неизвестный маршрут:** любой другой URL вернет **404 Not Found** с ошибкой `{"error": "Route not found"}`.

## 7. Результат проверки после перезапуска
Благодаря SQLite данные сохраняются на жестком диске в файле `data.db`.
**Процесс проверки:**
1. Запускаем сервер и создаем новую книгу через POST.
2. Останавливаем сервер (`Ctrl + C`).
3. Запускаем сервер заново (`npm start`).
4. Выполняем GET-запрос (`/api/books`).
**Результат:** Созданная книга остается в базе данных и успешно возвращается сервером. Данные не теряются при перезапуске процесса Node.js.
