# Практическая работа №5. Собственный сервер на Node.js и Express

## 1. Установка зависимостей и запуск проекта
Для запуска сервера на вашем компьютере должен быть установлен Node.js.
1. Откройте терминал и перейдите в папку с проектом: `cd internet-technologies/05`
2. Установите все необходимые библиотеки (в нашем случае это Express): `npm install`
3. Запустите сервер командой: `npm start`

После запуска в консоли появится сообщение `Server is running on http://localhost:3000`. Сервер будет ожидать запросы по этому адресу. Чтобы остановить сервер, нажмите `Ctrl + C` в терминале.

## 2. Описание выбранной сущности
В качестве предметной области для API выбраны **Книги (Books)**. 
На данном этапе база данных не используется: все записи хранятся в оперативной памяти в виде обычного JavaScript-массива. Это означает, что при перезапуске сервера все изменения (добавленные или удаленные книги) сбросятся к исходному состоянию.

Каждый объект книги имеет следующую структуру:
- `id` — уникальный числовой идентификатор (генерируется автоматически при создании).
- `title` — название книги (строка).
- `author` — имя автора (строка).
- `year` — год издания книги (число).
- `available` — логическое значение (true/false), показывающее, доступна ли книга в данный момент.

## 3. Маршруты API
Сервер реализует следующие маршруты:

| Метод | URL | Описание | Возможные статусы |
| :--- | :--- | :--- | :--- |
| GET | `/api/info` | Возвращает служебную информацию о сервере (имя, версия, текущее количество книг в базе). | 200 OK |
| GET | `/api/books` | Возвращает массив всех книг. Поддерживает фильтрацию через query-параметры. | 200 OK |
| GET | `/api/books/:id` | Возвращает одну конкретную книгу по её ID. Если книги с таким ID нет — возвращает ошибку. | 200 OK, 404 Not Found |
| POST | `/api/books` | Создает новую книгу. Принимает JSON в теле запроса. Если не хватает обязательных полей — возвращает ошибку. | 201 Created, 400 Bad Request |
| ANY | `*` (любой другой) | Перехватывает любые другие запросы к несуществующим маршрутам. | 404 Not Found |

## 4. Фильтрация через Query-параметры
Маршрут `GET /api/books` умеет фильтровать коллекцию. Параметры передаются в URL после знака `?`. Их можно комбинировать (через знак `&`).
- `GET /api/books?available=true` — вернет только те книги, которые доступны.
- `GET /api/books?author=Булгаков` — вернет книги, написанные Булгаковым (поиск не зависит от регистра).
- `GET /api/books?q=война` — вернет книги, в названии которых встречается слово "война" (поиск подстроки).
- `GET /api/books?author=Толстой&available=false` — вернет недоступные книги Толстого.

Если не передать ни один из этих параметров, сервер вернет полный список всех книг (как в базовом маршруте).

## 5. Примеры запросов и ответов

**Пример 1. Корректный POST-запрос (создание новой книги)**
Мы отправляем запрос через консоль с помощью `curl`:
`curl -X POST http://localhost:3000/api/books -H "Content-Type: application/json" -d '{"title":"Гарри Поттер","author":"Роулинг","year":1997,"available":true}'`

Сервер проверяет данные, генерирует новый `id` (например, 7), добавляет книгу в массив и возвращает статус **201 Created** и сам созданный объект:
`{"id":7,"title":"Гарри Поттер","author":"Роулинг","year":1997,"available":true}`

**Пример 2. Ошибочный POST-запрос (серверная валидация)**
Попробуем создать книгу без указания автора:
`curl -X POST http://localhost:3000/api/books -H "Content-Type: application/json" -d '{"title":"Книга без автора"}'`

Сервер видит, что обязательное поле `author` отсутствует, и возвращает статус **400 Bad Request** с описанием ошибки:
`{"error":"Поля title и author обязательны"}`

**Пример 3. Запрос несуществующего объекта**
Запрашиваем книгу с ID 999 (которой точно нет в базе):
`curl http://localhost:3000/api/books/999`

Сервер ищет её в массиве, не находит и возвращает статус **404 Not Found**:
`{"error":"Not found"}`

**Пример 4. Запрос несуществующего маршрута**
Попробуем обратиться к несуществующей странице API:
`curl http://localhost:3000/api/unknown-route`

Срабатывает middleware для обработки 404, и сервер возвращает статус **404 Not Found**:
`{"error":"Route not found"}`
