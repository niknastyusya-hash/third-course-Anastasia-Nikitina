# Занятие 3. Растеризация окружности: алгоритм средней точки

Реализация алгоритма средней точки для построения окружности на Canvas
без использования `ctx.arc()`. Сравнение с построением через формулу
`y = round(sqrt(r² − x²))`.

## Файлы

- `index.html` — форма, canvas, таблица шагов, блок эксперимента;
- `style.css` — внешний вид;
- `app.js` — алгоритм средней точки, симметрия, формула, эксперимент.

## Ответы на вопросы

**Как используется симметрия окружности?**

Для окружности с центром в начале координат точке `(x, y)` соответствуют
ещё семь точек: `(y, x)`, `(−x, y)`, `(−y, x)`, `(x, −y)`, `(y, −x)`,
`(−x, −y)`, `(−y, −x)`. В коде это отражено в функции `plot8(cx, cy, x, y)`,
которая добавляет к базовой точке `(x, y)` координаты центра `(cx, cy)`
и выводит сразу восемь пикселей.

**Почему достаточно строить одну восьмую?**

Из-за симметрии: восемь отражений точки `(x, y)` дают восемь точек
окружности. Если строить сектор от `x = 0` до `x = y` (то есть до
направления 45°), то все остальные точки окружности окажутся отражениями
уже построенных. Продолжать цикл нет смысла — это будет повтор.

**Что означает переменная d?**

`d` — решающая переменная. Это дискретная мера отклонения от идеальной
окружности. По знаку `d` выбирается следующий пиксель: если `d < 0`,
оставляем `y` прежним; если `d >= 0` — уменьшаем `y` на 1. `d` — не ошибка
программы, а рабочий инструмент, аналог переменной `error` в алгоритме
Брезенхема для отрезка.

**Когда уменьшается y?**

Когда `d >= 0`. Это означает, что средняя точка между двумя кандидатами
(E и SE) находится снаружи или на самой окружности — пора «повернуть»,
уменьшив `y` на 1. При `d < 0` середина ещё внутри окружности, поэтому
`y` оставляем прежним.

**Почему цикл заканчивается при x > y?**

Мы строим только один сектор — от верхней точки `(0, r)` до направления
45° (где `x = y`). После этого точки становятся отражениями уже
построенных — они получаются через `plot8`, но не через новые вычисления.
Если продолжить цикл, мы просто будем повторно рисовать те же пиксели.

**Совпали ли пиксели алгоритма средней точки и способа через формулу?**

Не всегда. На большинстве радиусов наборы совпадают, но в отдельных
точках могут отличаться на 1 пиксель. Это происходит там, где идеальная
окружность проходит почти посередине между двумя соседними клетками растра:
алгоритм средней точки и `round(sqrt(...))` могут принять разные решения.
Оба варианта корректны — они просто по-разному приближают окружность.

**Что показал небольшой эксперимент по времени?**

Оба способа на маленьких радиусах работают сопоставимо быстро, но
разница становится заметной при большом количестве построений. Алгоритм
средней точки использует только целочисленные операции (сложение,
вычитание, умножение на 2, сравнение), тогда как способ через формулу
каждый раз вычисляет квадратный корень и округляет вещественный
результат. По нескольким запускам 1000 окружностей видно, что средняя
точка обычно немного быстрее. Но главное — идея: вместо вычисления
точного значения можно хранить решающую переменную и обновлять её
небольшими приращениями.
