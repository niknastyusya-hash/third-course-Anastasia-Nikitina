# Занятие 2. Алгоритм Брезенхема для отрезка

Реализация алгоритма Брезенхема для растеризации отрезка, сравнение
с ЦДА (из занятия 1), таблица шагов и замер времени.

## Файлы

- `index.html` — форма, canvas, список пикселей, таблица, блок эксперимента;
- `style.css` — внешний вид;
- `app.js` — оба алгоритма, отрисовка, таблица, замер времени.

## Ответы на вопросы

**Чем идея Брезенхема отличается от ЦДА?**

ЦДА на каждом шаге прибавляет к координатам вещественные приращения
`xStep` и `yStep` и округляет текущее положение. Брезенхем не использует
дробей: он хранит целочисленную «ошибку» и по её значению решает, нужно ли
сдвинуться по x, по y или по обеим координатам. В основе — только
сложение, вычитание и сравнение.

**Для чего используется переменная error?**

`error` — накопленная мера отклонения идеальной прямой от текущего
пикселя. Чем больше `error`, тем сильнее мы «ушли» в одну сторону.
Проверки `error2 > -dy` и `error2 < dx` решают, пора ли сдвинуться по
соответствующей координате, чтобы вернуться ближе к идеальной линии.

**Зачем нужны sx и sy?**

`sx` и `sy` задают направление движения по каждой оси: `+1` — если идём
вправо/вниз, `-1` — если влево/вверх. Это позволяет использовать один и
тот же код для всех восьми направлений отрезка. Без них пришлось бы
писать отдельные ветки для каждого квадранта.

**Почему две проверки изменения координат нельзя бездумно заменить на if ... else?**

Потому что в некоторых шагах нужно менять **обе** координаты одновременно
(диагональный шаг). Если поставить `else if`, сработает только первая
проверка, и вторая координата «отстанет». Отрезок получится неправильным
для крутых/пологих диагоналей. Две проверки независимы: одна отвечает за x,
другая — за y.

**На каких входных данных вы обязательно проверяли программу?**

- Обычный наклонный отрезок: `(2, 2) → (8, 5)`.
- Горизонтальный: `(2, 5) → (20, 5)` — `dy = 0`.
- Вертикальный: `(7, 2) → (7, 20)` — `dx = 0`.
- Справа налево: `(20, 8) → (2, 3)` — `sx = -1`.
- Снизу вверх: `(5, 20) → (15, 2)` — `sy = -1`.
- Крутой наклон: `(3, 2) → (7, 25)` — `dy > dx`.
- Одна точка: `(10, 10) → (10, 10)` — цикл завершается сразу.

**Совпали ли наборы пикселей ЦДА и Брезенхема во всех ваших примерах?**

Нет, не во всех. На пологих и крутых наклонах наборы часто совпадают,
а на «промежуточных» углах могут отличаться в отдельных точках из-за
разного способа округления. Оба набора корректны — они просто по-разному
приближают идеальную прямую. Отличие обычно составляет 1–2 пикселя на
отрезке и проявляется в местах, где линия проходит почти посередине
между двумя соседними клетками.
